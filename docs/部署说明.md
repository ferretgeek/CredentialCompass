# 部署说明

推荐顺序：先用演示模式理解界面；真实使用优先回环监听 + SSH 隧道；确需公网域名时再加 HTTPS 反向代理。

## 本地演示

```powershell
py -3.10 -m venv .venv
.\.venv\Scripts\python -m pip install -e .
.\.venv\Scripts\python -m credential_compass --demo
```

终端会打印本地地址与一次性访问令牌。令牌不写入文件，进程重启后失效。

## 本地真实模式

先确认 CLIProxyAPI 管理端只在受信网络中可达。PowerShell 示例：

```powershell
$env:COMPASS_CPA_URL = "https://cliproxyapi.example.com"
$env:COMPASS_CPA_KEY = "<仅在本机填写管理密钥>"
$env:COMPASS_ACCESS_TOKEN = (.\.venv\Scripts\python -m credential_compass token)
.\.venv\Scripts\python -m credential_compass
```

实时额度探测和状态变更默认关闭。明确理解风险后才设置：

```powershell
$env:COMPASS_ENABLE_LIVE_PROBE = "true"
$env:COMPASS_ALLOW_STATUS_CHANGES = "true"
```

应用不会自动读取 `.env`。不要把真实值写进仓库、截图、Issue 或命令记录；服务端部署请使用权限为 `0600` 的环境文件或秘密管理器。

## Docker Compose

先在本地创建不提交的 `.env`，至少写入 32 字符以上的 `COMPASS_ACCESS_TOKEN`。默认 Compose 仍运行合成演示：

```bash
docker compose up --build
```

端口只发布到宿主机 `127.0.0.1:8788`，容器只读运行、丢弃 Linux capabilities，并限制进程、内存与 CPU。真实模式还需设置 `COMPASS_DEMO=false`、`COMPASS_CPA_URL` 和 `COMPASS_CPA_KEY`。若容器通过私网明文 HTTP 访问 CLIProxyAPI，必须显式设置 `COMPASS_ALLOW_PRIVATE_HTTP=true`；能用 HTTPS 时不要开启。

## Linux + systemd

1. 创建专用系统用户，把虚拟环境安装到 `/opt/credential-compass/.venv`。
2. 将 [`deploy/credential-compass.service`](../deploy/credential-compass.service) 复制到 `/etc/systemd/system/`。
3. 从 [`deploy/credential-compass.env.example`](../deploy/credential-compass.env.example) 创建 `/etc/credential-compass.env`，填入真实值后执行 `chmod 600 /etc/credential-compass.env`。
4. 修改服务文件中的用户与路径，随后 `systemctl daemon-reload && systemctl enable --now credential-compass`。

服务默认监听 `127.0.0.1:8788`，不要直接暴露到公网。

## HTTPS 反向代理

参考 [`deploy/nginx.conf.example`](../deploy/nginx.conf.example)。将示例域名替换为自己的域名，把同一域名加入 `COMPASS_ALLOWED_HOSTS`，并由受信代理终止 TLS。代理必须保留原始 `Host`；不要关闭应用的 Host/Origin 检查。

远程个人使用更推荐 SSH 隧道：

```bash
ssh -L 8788:127.0.0.1:8788 your-server
```

随后只访问 `http://127.0.0.1:8788`。

## 上线复核

- 未登录窗口可打开静态首页，但所有状态 API 均返回 401。
- 错误 Host、跨域 Origin 和跨端口 Origin 被拒绝。
- 浏览器存储中只有主题名；刷新后需重新输入访问令牌。
- 管理密钥、账号与上游正文不出现在页面源代码、网络响应、日志或截图。
- 实时探测与状态变更只在确有需要时开启。
