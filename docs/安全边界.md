# 安全边界

凭证罗盘采用“浏览器假设不可信、公开仓库假设会被逐字扫描”的设计。

## 数据流

1. 部署者通过进程环境固定 CLIProxyAPI 根地址与管理密钥。
2. 服务端只访问固定的管理路由；不跟随重定向，响应最多读取 512 KiB。
3. 凭证文件 ID 立即转换为进程内 HMAC 句柄；账号默认遮罩。
4. 可选探测响应在内存中归类为健康状态、计划、用量与重置时间，原始正文随即丢弃。
5. 浏览器只接收匿名句柄、账号视图和归类后的结果；访问令牌只留在当前页面内存。

## 默认门禁

- 监听 `127.0.0.1`；非回环监听要求至少 32 字符的访问令牌和精确 Host 白名单。
- Host、Origin（含端口）与 `Sec-Fetch-Site` 校验；无 CORS，配套 CSP、点击劫持防护与速率限制。
- 请求体最大 32 KiB；上游响应最大 512 KiB；最多 10,000 个账号、并发最多 8、超时最多 30 秒。
- 明文 HTTP 默认只允许回环地址；私网 HTTP 必须显式开启，公网应使用 HTTPS。
- 实时探测与状态变更均默认关闭；状态变更最多 50 条、仅支持可逆的停用/恢复，并要求 `DISABLE N` 或 `ENABLE N` 精确确认。

## 明确不提供

- 原始 Token、凭证文件、上游正文、真实文件 ID 或管理密钥的读取与下载。
- 任意 URL 代理、网页端上游配置、重定向跟随、批量 ZIP、不可逆删除。
- Cookie、会话存储中的访问令牌、遥测、第三方脚本、字体或 CDN。

`localStorage` 只保存主题名。日志只记录本地启动信息；HTTP 请求日志被关闭，静默记录中不含账号或 Token。

## 仍由部署者负责

保护操作系统、浏览器与扩展、反向代理、CLIProxyAPI、上游账户及环境变量；限制进程与环境文件读取权限；为远程访问配置 TLS；轮换曾经泄露的秘密。凭证罗盘不能修复已被攻陷的依赖系统。
